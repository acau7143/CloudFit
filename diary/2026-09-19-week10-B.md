## 왜 이 기술/방법을 선택했는가
| 항목 | 선택한 것 | 대안 | 선택 이유 |
|------|-----------|------|-----------|
| 할인율 산정 | Retail Prices API 1회 실측 조회 후 하드코딩 교체 | 근사치 유지 / 추천 생성마다 실시간 API 연동 | 근사치는 API 응답에서 정밀값처럼 노출되는 문제가 있고, 실시간 연동은 이번 주 일정(Day4~5)에 부담이 큼 |
| uptime_ratio_7d 판정 근거 | "레코드 존재 = VM 가동 중" | 별도 uptime 컬럼 추가 | `azure_exporter.py`가 VM 내부 cron으로 도는 구조라, VM이 꺼지면 레코드 자체가 자연스럽게 비어 전제가 안전하게 성립 |
| Grafana 대시보드 구조 | 대시보드 3개 분리 + 태그 기반 Dashboard Link | 패널을 Row로 그룹핑 | 발표 데모 스토리텔링(자원 현황 → 이상탐지 → 비용 최적화)에 유리하고, 패널 과밀 문제를 근본적으로 해소 |

## 오늘 처음 안 사실
| 몰랐던 것 | 알게 된 것 | 왜 그렇게 되는지 |
|-----------|-----------|----------------|
| Retail Prices API의 Reservation 항목 `unitOfMeasure` | "1 Hour"로 표시되지만 실제 `retailPrice`는 약정 기간 전체 총액 | Consumption 항목과 필드 구조를 억지로 맞추다 생긴 API 표기 오류(알려진 이슈) |
| `Standard_B2ats_v2`의 RI 지원 여부 | 지원함 (이전엔 "B-시리즈는 RI 미지원"으로 잘못 추정돼 있었음) | 실제 `type eq 'Reservation'` 쿼리에서 1년/3년 항목이 정상 응답됨을 확인 |
| Grafana Dashboard Link의 "Dashboards" Type | 개별 대시보드를 하나씩 고르는 게 아니라, 지정한 태그를 가진 대시보드들을 자동으로 드롭다운에 모아줌 | 먼저 대시보드 3개에 공통 태그를 달아야 링크가 정상 동작 |
