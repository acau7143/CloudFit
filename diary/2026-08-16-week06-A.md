## 왜 이 기술/방법을 선택했는가
| 항목 | 선택한 것 | 대안 | 선택 이유 |
|------|-----------|------|-----------|
| 비용 수집 주기 | `--costs` 플래그로 자원과 분리, 하루 1회만 | 매 실행마다 비용도 같이 조회 | Cost Explorer는 호출당 과금(건당 $0.01) → 5분마다 부르면 하루 약 $2.88 낭비. 원래 스크립트는 플래그 없이 매번 호출해서 코드 수정 |
| 크론 등록 방식 | `crontab -e`로 직접 편집 | `(crontab -l; echo ...) \| crontab -` | Day4는 처음 등록이라 전체 내용을 눈으로 보며 확인하는 게 안전, 이후 항목 추가는 파이프 방식으로 전환 |
| 파일 수정 방식 | Python 스크립트로 특정 문자열 치환 | `sed`/`vi` 직접 편집 | 원격 터미널 붙여넣기 중 heredoc이 꼬이는 문제가 반복되어, 고유 문자열 매칭 방식이 더 안전 |

## 오늘 처음 안 사실
| 몰랐던 것 | 알게 된 것 | 왜 그렇게 되는지 |
|-----------|-----------|----------------|
| Amazon Linux 2023엔 cron이 기본 설치된 줄 알았음 | `cronie` 패키지를 따로 설치해야 `crontab` 명령어 사용 가능 | AL2023은 최소 설치 기준이라 cron 데몬이 기본 포함 안 됨 |
| Cost Explorer 호출이 무료인 줄 알았음 | **API 호출 자체가 건당 과금**(약 $0.01/call) | 비용 관리 프로젝트에서 비용 관리 API가 비용을 만드는 역설을 사전에 인지, 크론 설계에 반영 |
| CloudShell과 EC2 SSH를 헷갈림 | 둘 다 터미널처럼 보이지만 **완전히 다른 서버** (프로젝트 파일 유무로 구분 가능) | CloudShell은 AWS가 제공하는 임시 브라우저 서버, EC2는 실제 배포 대상 인스턴스 |
