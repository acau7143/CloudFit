## 왜 이 기술/방법을 선택했는가
| 항목 | 선택한 것 | 대안 | 선택 이유 |
|------|-----------|------|-----------|
| 약정 할인율 산정 | AWS Price List API 1회 조회 후 하드코딩 교체 | 근사치 유지, 실시간 API 연동 | `decisions/0012` 합의사항 그대로 — 실시간 연동은 이번 주 일정(README·발표자료 남음)에 부담 큼, 근사치 유지는 정확도 문제 그대로 남음 |
| pricing API 인증 | EC2에 IAM 사용자(`wjh61734-collector`) 프로필 별도 추가 | 인스턴스 role(`CloudWatchAgentRole`)에 pricing 권한 추가 | 공유 서버라 role 권한을 넓히면 다른 팀원 작업에 영향 줄 수 있음. 프로필 추가는 범위가 좁고 되돌리기도 쉬움 |
| requirements.txt 버전 | EC2에 이미 설치돼서 검증된 버전을 `pip3 show`로 그대로 채택 | 최신 버전으로 새로 채우기 | 이미 돌아가고 있는 버전이 재현성이 보장됨. 최신 버전으로 바꾸면 오히려 지금 안 나던 호환성 문제가 새로 생길 수 있음 |

## 오늘 처음 안 사실
| 몰랐던 것 | 알게 된 것 | 왜 그렇게 되는지 |
|-----------|-----------|----------------|
| AWS Price List API 리전 | 조회 대상 인스턴스 리전과 무관하게 API 자체는 항상 `us-east-1`에서만 서비스됨 | Price List API가 전역(글로벌) 카탈로그 성격이라 단일 리전에만 배포돼 있음 |
| EC2에서 인증 우선순위 | `~/.aws/credentials`에 값이 있으면 인스턴스 role보다 그게 먼저 쓰임 (`aws sts get-caller-identity`로 `Arn`이 `user/...`인지 `assumed-role/...`인지로 구분 가능) | boto3의 자격증명 탐색 순서상 명시적 프로필/환경변수가 인스턴스 메타데이터(IMDS)보다 우선함 |
| runbook 문서 드리프트 | runbook엔 IAM 사용자명이 `finops-collector`로 적혀있는데 실제 IAM 사용자는 `wjh61734-collector` | 초기 계획 문서를 만든 뒤 실제로 사용자를 생성할 때 이름이 바뀌었는데 문서에 반영이 안 됨 |
| git 바이너리 diff 표시 | 바이너리로 인식된 파일 교체는 커밋 로그에 `0 insertions(+), 0 deletions(-)`로 표시될 수 있음 (`git diff --stat`으론 `Bin X -> Y bytes`로 따로 표시) | git이 바이너리 파일은 줄 단위 변경을 셀 수 없어서 요약 줄엔 0/0으로만 나오고, 실제 변경 여부는 별도 Bin 표기로 확인해야 함 |
| decisions 번호 관리 | `decisions/` 파일 번호가 팀 전체가 아니라 브랜치별로 각자 매겨지고 있었음 (같은 `0003`인데 브랜치마다 완전히 다른 내용) | 브랜치를 나눠서 작업하다 보니 번호를 팀 차원에서 조율할 시점이 없었음 — main 병합 시점에야 충돌이 드러나는 구조 |
