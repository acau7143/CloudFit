# 2026-07-24 — Week 04 (A / 서버·DB 담당)

## 오늘 목표
- 중앙 서버(FastAPI)와 DB(PostgreSQL)를 Docker Compose로 구축
- `db/schema.sql`을 3주차 합의(공통 스키마 + cost_records 분리)대로 작성
- 수집기 → API → DB 저장 → 조회 전체 흐름을 컨테이너 환경에서 검증

## 오늘 한 일
- **컨테이너 환경 준비**: WSL2 설치(`wsl --install`) + 재부팅, Docker Desktop 설치·기동
- **`docker-compose.yml`**: `db`(postgres:15) + `server` 두 서비스, healthcheck(`pg_isready`), `depends_on: service_healthy`, schema.sql 자동 실행 마운트
- **`db/schema.sql`**: `resource_metrics` / `cost_records` 두 테이블 (GCP 기준, `cost_records`에 `currency` 포함)
- **`server/`**
  - `database.py`: `asyncpg` + SQLAlchemy 비동기 엔진, `get_db()` 세션
  - `main.py`: `/health`, `POST/GET /resources`, `POST/GET /costs` (공통 스키마 Pydantic 모델)
  - `Dockerfile`, `requirements.txt`
- **기동/검증**
  - `docker compose up -d db` → `\dt`로 두 테이블 생성 확인
  - `docker compose up --build -d` → 서버 이미지 빌드 + `finops_server` 기동, `/health` → `{"status":"ok"}`
  - `POST /resources` 저장 → `GET /resources`로 방금 넣은 데이터 조회 성공
- **`runbook/server-setup.md`** 작성

## 왜 이 기술/방법을 선택했는가
| 항목 | 선택한 것 | 대안 | 선택 이유 |
|------|-----------|------|-----------|
| DB 실행 방식 | PostgreSQL 컨테이너(Docker Compose) | 로컬 직접 설치 | 팀원 전원이 `docker compose up` 한 줄로 동일 환경 재현, 환경 오염 방지 |
| DB 드라이버 | `asyncpg` (비동기) | `psycopg2` (동기) | FastAPI async와 궁합이 좋고 여러 수집기의 동시 요청 처리에 유리 |
| 테이블 구조 | resource_metrics / cost_records **분리** | 한 테이블에 통합 | 수집 주기(5분 vs 하루)·단위(% vs USD)가 달라 통합 시 NULL 남발 (decisions/0002) |
| 시간/날짜 처리 | 파이썬에서 `datetime`/`date`로 변환 후 insert | SQL 캐스팅에 의존 | asyncpg가 타입에 엄격해 명시적 변환이 가장 확실하고 읽기 쉬움 |
| 서버 기동 순서 | `depends_on: service_healthy` | 단순 `depends_on` | DB가 완전히 준비된 뒤 서버가 붙게 해 초기 연결 실패 방지 |

## 오늘 처음 안 사실
| 몰랐던 것 | 알게 된 것 | 왜 그렇게 되는지 |
|-----------|-----------|----------------|
| asyncpg도 문자열 시간을 알아서 변환하는 줄 알았음 | **datetime/date 객체를 요구**, 문자열이면 500 에러 | 성능을 위해 psycopg2와 달리 암시적 캐스팅을 안 함 → 앱에서 변환 필요 |
| schema.sql은 컨테이너 켤 때마다 실행되는 줄 알았음 | **볼륨이 비어 있는 최초 기동 시에만** 실행 | `docker-entrypoint-initdb.d`는 초기화용. 스키마 바꾸면 `down -v`로 볼륨 삭제 후 재기동 |
| 컨테이너는 뜨면 바로 쓸 수 있는 줄 알았음 | DB가 "떴다"와 "받을 준비됨"은 다름 | healthcheck(`pg_isready`) 통과 후에야 서버가 붙어야 안정적 |
| WSL만 깔면 Docker가 바로 되는 줄 알았음 | WSL2 설치 후 **재부팅해야** Docker 엔진이 올라옴 | 커널/가상화 레벨 변경이라 재시작이 필요 |

## 막힌 점
- 새 노트북에 WSL2가 없어 Docker Desktop이 안 켜짐 → `wsl --install` + 재부팅 후 해결
- Docker 엔진이 "Starting..."에서 멈춤 → WSL 설치 직후라 재부팅으로 해결
- `POST /resources`가 500 → asyncpg가 문자열 `timestamp`/`date`를 거부 → `datetime.fromisoformat` / `date.fromisoformat`로 변환해 해결
- `.git/index.lock` 찌꺼기로 커밋 막힘 → 락 파일 삭제로 해결
