  기존 aws_exporter(REGION 고정), gcp_exporter(ZONE 고정) 컨벤션과 통일

- 테스트용 공인 IP(`test-unused-ip`) 생성 후 미연결 상태로 방치 → 탐지 확인
- 테스트용 데이터 디스크(`test-unused-disk`)를 VM에 붙였다가 분리 → 탐지 확인

## 왜 이 기술/방법을 선택했는가
| 항목 | 선택한 것 | 대안 | 선택 이유 |
|------|-----------|------|-----------|
| 미사용 판정 방식 | Azure SDK로 직접 상태값(`disk_state`, `ip_configuration`) 조회 | Azure Advisor Recommendations API | 팀 공통 스키마·패턴 통일 (다른 클라우드도 직접 조회 방식) |
| 스캔 범위 | `AZURE_RESOURCE_GROUP` 하나로 한정 | subscription 전체 스캔 | AWS(REGION 고정), GCP(ZONE 고정)와 스코프 컨벤션 통일. 권한 범위도 일치시켜 오탐(권한 없어 빈 목록) 위험 축소 |
| IP 오탐 방지 | 서버의 이전 활성 목록과 대조해 재탐지 시에만 확정 | 생성 시각 기준 유예 기간 | 공인 IP 리소스에 생성 시각 필드 자체가 없음(API 확인 완료). Activity Log 조회는 리소스마다 추가 API 호출 필요해 과함 |
| 클라우드 간 import | `collectors/azure_unused_detector.py`에서 `sys.path`에 프로젝트 루트 직접 추가 | 매 실행 시 `PYTHONPATH` 환경변수 수동 설정 | 팀원(A, C)도 동일 패턴(`from server.notifier import ...`)을 쓸 예정이라, 환경변수 설정 없이 바로 동작하게 하는 게 안전 |

## 오늘 처음 안 사실
| 몰랐던 것 | 알게 된 것 | 왜 그렇게 되는지 |
|-----------|-----------|----------------|
| `disk_state`가 `Unattached`/`Attached` 둘뿐일 거라 생각함 | `Reserved`, `Frozen`, `ActiveSAS` 등 6개 이상의 값이 있음 | `Reserved`는 "VM은 있는데 정지된 상태"라 미사용과 다름. 정확히 `Unattached` 문자열 매칭이 필요한 이유 |
| Python이 형제 폴더(collectors/ ↔ server/)도 알아서 찾아줄 거라 생각함 | `__init__.py`를 만들어도, 스크립트가 있는 폴더 밖은 기본적으로 안 뒤짐 | Python은 실행한 스크립트의 디렉터리만 `sys.path`에 자동으로 넣음. 부모 디렉터리는 명시적으로 추가해야 함 |
| 공인 IP도 디스크처럼 생성 시각을 조회할 수 있을 거라 생각함 | `PublicIPAddress` 모델엔 생성 시각 필드가 아예 없음 | 생성 시각이 필요하면 Activity Log를 리소스별로 따로 조회해야 하는데, 리소스 하나하나 추가 호출이 필요해 비용이 큼 |
| PowerShell에서 curl로 한글 보내면 문제없을 거라 생각함 | `Invoke-RestMethod`로 보낸 한글이 Slack에서 깨짐(`??? ???`) | PowerShell 기본 인코딩이 UTF-8이 아니라서. Python `requests`는 기본이 UTF-8이라 실제 코드에선 문제 없음 |
