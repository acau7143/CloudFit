## 3. 팀장 피드백 분석 (⭐ 중요 — 2주차 전 필수 수정)

**총평**: VPC/Subnet/Route table/Instance 모두 잘 생성, 보안그룹/OS계정/IAM/MFA/NAT 설정 잘 이행. 메일 형식·자산관리문서 Good. "용어를 검색해서 더 깊이 공부하면 도움" 코멘트.

**팀장 Q&A**: "반복 실습이 필요한지" 질문에 → **"반복학습만이 답입니다."** 실무도 자주 하는 일은 매뉴얼 없이 손에 익음.

**⚠️ 지금 고쳐야 할 것 2가지:**

**1. 보안그룹 오타** — mission-bastion-sg의 "All TCP" 인바운드 Source가 `0.0.0.0/16`으로 됨 (원래 `10.0.0.0/16`, "1"이 빠짐). → EC2 > Security Groups > mission-bastion-sg > Inbound rules 편집. **안 고치면 2주차에 에러.**

**2. NAT instance의 IP Forwarding 설정 누락** — 가이드 51p 단계:
```bash
sudo bash -c 'echo "net.ipv4.ip_forward=1" > /etc/sysctl.d/custom-ip-forwarding.conf'
sudo sysctl -p /etc/sysctl.d/custom-ip-forwarding.conf
```
Private subnet 인스턴스가 보낸 패킷을 NAT instance가 전달(forward)할 수 있게 커널 설정을 켜는 단계. iptables MASQUERADE만으론 부족. **안 하면 2주차 에러.**

## 4. 수정 실행 기록

**1번 완료**: Source `0.0.0.0/16` → `10.0.0.0/16` 반영.

**2번 진행 중 막힘 → 해결**:
- SSH 접속 개념 혼동: AWS 콘솔 로그인(웹, IAM 계정)과 SSH 접속(리눅스 서버 admin 계정, 비번 11111111)은 완전히 별개.
- `ssh admin@43.200.43.153` 접속 안 됨 → `Connection timed out` → **원인: 내 공인 IP가 바뀜**. 보안그룹 SSH 규칙 Source를 "My IP"로 재설정하니 해결.
- IP 바뀌는 이유: (1) 장소 바뀌면 100%, (2) 같은 집이라도 유동 IP라 시간 지나면 바뀜.
- 접속 후 IP forwarding 두 명령어 실행 → `net.ipv4.ip_forward = 1` 출력 확인. 파일에 저장돼 재부팅해도 유지.
