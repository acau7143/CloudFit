# 대화 백업 — 계획서 분석 · 캡스톤 계획 · 노션 템플릿

> 원본 세션: "1주차" (프로젝트 초기 기획 단계)
> 내용: 한이음 수행계획서 분석 → 3명 팀 10주 로드맵 검토 → 캡스톤 선발 후 확장 계획 → 노션 템플릿 구성

---

## 1. 한이음 수행계획서 분석

**한 줄 요약**: AWS·Azure·GCP 멀티클라우드 환경의 VM 자원 사용량과 비용 정보를
수집 → 통합저장 → 분석 → 최적화 추천 → 시각화까지 하나의 흐름으로 묶는 **FinOps 지원 시스템**.

**기술적으로 가장 위험한 지점:**
1. 클라우드 3사의 비용 API가 구조·지연·granularity가 전부 다름. 비용 데이터는 수 시간~24시간 지연. 공통 스키마로 정규화하는 게 과제의 절반.
2. 메모리·디스크 사용률은 기본 제공 안 됨 — AWS CloudWatch Agent, Azure Monitor Agent, GCP Ops Agent를 VM마다 설치해야 함. 계획서에 이 작업이 빠져 있음.
3. 테스트 계정/무료 크레딧으로는 "저활용·과대할당" 패턴이 안 나옴 → 합성 부하 데이터 필요.
4. 추천 기준의 정량성 — "왜 그 임계값이냐"의 근거 문서화 필요.

## 2. 3명 팀 10주 로드맵 검토 (6/23~8/31)

원래 계획: 1주차 분석+설계 → 2~3주차 수집 모듈 병렬 → 4~5주차 중앙서버+DB → 6~7주차 분석+ML → 8~9주차 대시보드+통합테스트 → 10주차 마무리.

**지적한 함정:**
1. ⚠️ Azure 크레딧이 30일이면 만료 — 일정과 정면충돌. 분석·ML 구간에 이미 크레딧이 죽음. GCP는 $300/90일. AWS도 2025년부터 크레딧 기반으로 변경.
2. ⚠️ "비용 데이터"는 사용량처럼 안 쌓임 — 일 단위, 지연됨. 무료 크레딧 VM은 실제 청구액이 거의 0. **대응: Pricing API로 이론 비용 계산** (사용률 실측 × 단가). 이게 차별화 포인트.
3. 메모리·디스크 메트릭 에이전트 설치가 빠짐 — 1주차 VM 켤 때 에이전트 설치까지 한 세트로.
4. ML을 SageMaker/Vertex로 가는 건 과잉 — 로컬 scikit-learn IsolationForest로 시작(무료).
5. 통합을 8주차까지 미루면 거기서 다 터짐 — 5주차쯤 "walking skeleton"(AWS 한 곳 × CPU 한 지표만 수집→DB→그래프까지 얇게 관통).
6. 1인 1클라우드의 단일 장애점 — 공통 수집 인터페이스를 1주차에 먼저 합의.

## 3. "셋 다 클라우드 처음" — 학습 중심 조언

**핵심: "1인 1클라우드 동시 시작"을 뒤로 미뤄라.**
먼저 셋이 같이 AWS 하나만 끝까지 → 그 패턴을 복제해서 Azure/GCP로 나눔.
- AWS 추천 이유: 한글 자료가 제일 많음.
- "수집→DB→단순 그래프"까지 AWS 한 곳으로 전 구간 관통하면, 프로젝트가 어떻게 굴러가는지 몸으로 이해.

**초보가 꼭 지킬 안전 2가지:**
1. 액세스 키를 절대 GitHub에 올리지 마. `.env` + `.gitignore`. (봇이 키 찾아내 채굴 악용 → 수백만원 청구 사고 흔함)
2. 첫날 예산 알림(Budget Alert)부터 걸어라. 월 $5 초과 시 메일.

## 4. 캡스톤 선발 후 — "최대한 많이 도전" 계획

> 원칙: **8월 중순까지 "코어"를 끝내라. 그래야 남은 시간을 마음껏 실험에 쓴다.**

**코어(반드시):** 1~2개 클라우드 수집 → 중앙 DB → 규칙 기반 분석/추천 → 대시보드.

**그 위에 얹을 도전 트랙:**
- A. AI/ML: IsolationForest 이상탐지 → 비용 추세 예측(Prophet/ARIMA) → LLM 리포트 생성
- B. 자동화/액션(FinOps의 꽃): 저활용 VM 자동 중지, 야간 on/off, Slack/이메일 알림
- C. 인프라 자동화(취업 직결): Terraform(IaC), Docker Compose, GitHub Actions
- D. 데이터/거버넌스: 태그 기반 부서별 비용 정산(chargeback)
- E. 프론트엔드: Grafana → React 커스텀 대시보드

도전 트랙을 1인 1트랙으로 나누면 팀 전체 지식의 폭이 최대가 됨.

## 5. 노션 템플릿 구성안

팀 지식 허브(코드는 GitHub, 일정은 WBS) 관점:
1. 홈 대시보드 — 프로젝트 소개, 현재 주차, 링크 모음
2. 회의록 DB — 날짜/참석자/결정사항/다음 할 일 (주 3회 미팅)
3. 작업 보드(칸반) — 할 일/진행/리뷰/완료 + 담당자·마감일·클라우드 태그
4. 📚 학습 노트/위키 ⭐ — 초보 팀에 제일 중요. 한 명이 뚫은 걸 셋이 안 헤매게
5. 🔧 트러블슈팅 로그 DB ⭐ — 증상/원인/해결/클라우드. 발표 "삽질 회고"로도 활용
6. 기술 문서 모음 — 아키텍처/수집 항목/판별 기준/DB 스키마/API 명세
7. 산출물 트래커 — 소스코드/보고서/논문/시연영상/발표자료
8. 자료실/참고 링크 (⚠️ 키·비밀번호 절대 금지)
9. Ground Rule 페이지

처음엔 1~5번만 먼저. 빈 페이지 많으면 아무도 안 씀.
